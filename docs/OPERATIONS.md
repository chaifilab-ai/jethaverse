# JethaVerse (formerly Jethiya, Gokuldham Guide): operations

How the app is put together and how to change it without breaking it. Read this with `docs/SPEC.md` and `CHANGELOG.md`.

## At a glance

- **What it is:** a static site with no backend, no login and no database. One screen: a search box, a building of 12 windows (the characters) and a lift panel of results. It covers all 4,872 episodes SonyLIV lists.
- **Data:** `data/episodes.js` (and the same data as `data/episodes.json`), generated by `tools/build_data.py`. Don't edit them by hand.
- **User state, per browser, in `localStorage`:**

  | Key | Holds |
  |---|---|
  | `gokuldham.watched.v1` | JSON array of watched episode numbers |
  | `gokuldham.saved.v1` | JSON array of saved episode numbers |
  | `gokuldham.night.v1` | `true` / `false`: night mode (first visit follows the phone's dark setting) |

- **Third parties at runtime:**

  | Service | What for |
  |---|---|
  | Google Fonts | Anton (display) and Hind (text, with Devanagari). Without them the app uses system fonts. |
  | youtube.com | "Watch on YouTube" links (plain https; the phone may hand them to the YouTube app) |
  | sonyliv.com | "Open on SonyLIV" links for the few episodes with no free upload (Premium) |

  The app does not embed a YouTube player or load thumbnails any more (v2.0.0).

## Run it

- **Locally:** `python tools/serve.py`, then open http://localhost:5317 (run it from this folder).
- **Without a server:** double-click `index.html`. It works: the data loads through a script tag.
- **Tests:** `npm test` (or `node --test tests/search.test.js`). Needs Node 18+.
- **One-file version** (for phones; opens full-screen in the browser): `python tools/build_single.py` writes `dist/JethaVerse.html` (about 3.3 MB, data and stickers inside; only the fonts load from Google Fonts). Send or host that one file. Rebuild it after every data rebuild.
- **Hosted single page** (a claude.ai artifact): `python tools/build_artifact.py` writes `dist/artifact/` (`index.html`, `data/episodes.json`, `assets/stickers/`). It inlines the CSS and JS and sets `GG_CONFIG = {noHash}`; the page fetches `data/episodes.json`. Publish `index.html` together with the `data/` and `assets/` files.

## Data model (`data/episodes.js`)

| Field | Meaning |
|---|---|
| `episodes[].n` | episode number (1-4876; 3859-3862 do not exist on SonyLIV) |
| `title`, `synopsis` | SonyLIV's title and full synopsis |
| `cast[]` | who is in the episode. Episodes 1-50: confirmed by hand from the Hindi captions. Others: names in the SonyLIV text (plus phrases like "Hathi's son"), and for videos with captions, names heard often enough in them (`castBy: "c"`), or in short official clips of the same episode (`"k"`); otherwise text only (`"t"`). |
| `maybe[]` | caption mentions below a character's threshold (Episodes 51+ with captions) |
| `videoId`, `channel`, `minutes` | the best free upload (null when there is none: 52 episodes) |
| `watch[]` | every known upload, best first: `{label, note, url, id, quality, minutes}` |
| `check` | `1` when the video's own description fits a neighbouring number slightly better (436 episodes). The sheet shows a gentle warning. |
| `summary`, `events[]`, `maybe[]`, `arcs[]`, `confidence`, `views`, `uploaded`, `note` | Episodes 1-50 only |
| `characters` (top level) | `{about, aliases[]}`: aliases drive name search (English + Devanagari) |
| `families`, `arcs` (top level) | kept for Episodes 1-50 and the search index |

`js/search.js` fills in missing `summary`, `events`, `arcs`, `maybe` and `cast` when it builds the index, so rows without them are fine.

## Common changes

- **Add or fix a character:** edit `CHARACTERS`, `FAMILIES` and `RELATIONS` in `tools/characters.py` (shared by the data builder and `pipeline/cast/`), run `python pipeline/cast/count_names.py` and `python pipeline/cast/thresholds.py` if you added Hindi aliases, then `python tools/build_data.py research data/episodes.js`, `npm test` and `npm run test:py`. The 12 windows are listed in `ROWS` at the top of `start()` in `js/app.js`.
- **Add a search synonym:** edit `SYN` in `js/search.js`, then add a test case.
- **Refresh the catalogue** (new episodes, better links): re-run the pipeline steps below, rebuild the Excel (`python pipeline/build_excel.py`, then copy it to the project root), then run `build_data.py`. `build_data.py` reads the "All episodes (best link)" sheet and `pipeline/alt/fallback.json`.
- **Change the look:** edit `css/tokens.css` first. The building and sky colours are custom properties on `.app` and `.app.night` in `css/app.css`.
- **New sticker poses:** run `python tools/make_stickers.py sheet1.png sheet2.png hero.png assets/stickers`. Sheets are 3x2 grids on white.

## Staying current (automation)

Two scripts keep the list fresh. They only write `data/live.json` (the changes) and `data/live_state.json` (their notebook); the big generated files `data/episodes.js` / `.json` are never touched by them.

| Script | What it does | When |
|---|---|---|
| `python tools/sync_new.py` | Reads the newest uploads of the official channel, Sony SAB and Sony PAL (public feeds, no key). Adds full-length uploads as links, adds new episode numbers, labels 10-minute "NEW! Ep" videos as highlights. `--deep 150` looks further back (needs yt-dlp); `--dry` saves nothing. | every 3 hours |
| `python tools/check_links.py` | Asks YouTube whether each link still exists (a seventh of them a day; `--all` for all). Two "gone" answers on different days retire a link; an episode left without a full-length link gets a spare from `tools/pool.json`. | once a day |
| `python tools/build_pool.py` | Rebuilds `tools/pool.json` from the channel listings in `pipeline/alt/`. | by hand, after re-listing the channels |

- **Where it runs:** `.github/workflows/update.yml`. On GitHub it runs by itself every 3 hours, tests the result, commits `data/live.json` and republishes the site (Settings -> Pages -> Source: GitHub Actions). A failed run emails the repository owner; the site keeps its last good list. By hand: Actions -> "Update and publish" -> Run workflow, or locally `npm run update`.
- **How the app uses it:** `S.applyLive(data, live)` in `js/search.js` lays the file over the built-in list every time the app starts: dead links are dropped, added links are appended (full-length first, then short uploads, then highlights), new episodes are added. The app starts with the newest copy it has (packed into the one-file version, or kept in `localStorage` under `gokuldham.live.v1`), then fetches `data/live.json` and re-draws if it is newer. `GG_CONFIG.live` is the address to ask: beside the page by default; for the one-file version it is `liveUrl` in `site.config.json` (empty = do not ask).
- **`data/live.json`:** `{"dead": [ids], "links": {"601": [{"id", "label", "kind": "full" | "highlights", "minutes", "added", "check"?, "note"?}]}, "episodes": {"4877": {"title", "synopsis", "aired", "cast", "added"}}, "updated", "checked"}`. To undo something the job did, delete the entry and commit; to hide a wrong link for good, add its id to `dead`.
- **Folding the changes in:** the file can grow for years (about 150 bytes per link). When the catalogue is rebuilt from the pipeline, the same links come in through the normal route and `data/live.json` can be emptied.
- **Safety rules in the scripts:** a new episode number must be at most 40 past the newest known one and come from the official channel or Sony SAB; a video counts as full-length only at 15 minutes or more (17 to 23 is normal) and at most 40; one run in which more than 5% of links answer "gone" is treated as a broken run and changes nothing; a network error never counts against a link.

## Known limits

- **Links are checked by word overlap, not by watching.** 436 links carry a "may not match" note. Episodes 1-50 were checked against the video captions.
- **52 episodes have no free upload** (the newest numbers and some scattered ones). The sheet links to SonyLIV (Premium).
- **Cast is a best guess for Episodes 51+.** Measured on the 50 hand-checked episodes, text names alone found 29% of the true cast (84% of the names listed were right). Text plus captions found 61% (84% right). Only 2,019 videos have captions (all 302 official, 1,717 of Sony PAL's 2,783; Sony SAB has none), so the 1,145 text-only episodes sit near the 29% figure. 1,708 episodes (mostly Sony SAB) get names from short official clips of the same episode instead; against the full-video cast that raised recall from 53% to 65% at 92% precision. 126 episodes list nobody. Goli is not found from captions: the Hindi word is also "bullet", "pill" and "marbles" (a Tapu Sena game); the best rule tried was right about 1 time in 6 on the hand-checked episodes, so it was left out.
- **Video availability depends on YouTube.** An upload can be removed or made private. The daily job notices within about 8 days (a weekly check plus a second look the next day) and switches to a backup or a spare; until then the dead link is still shown. Episodes with no other full-length upload anywhere fall back to "SonyLIV only".
- **New episodes start as highlights.** The full episode reaches YouTube about three weeks after it airs. Until then the title is the official channel's Hindi-English one and the synopsis is the channel's; who is in it is read from that text only.
- **The automation reads YouTube's public pages, not an official API.** If YouTube changes its feed or page format the job fails loudly (a failed run, an email) rather than writing bad data; the fix is in `tools/live_common.py`. The feed lists only a channel's 15 newest uploads plus its 15 newest long videos, so a full episode missed during a long outage needs `--deep`.
- **The automation is not running yet.** It was run by hand on 2026-11-26. It runs by itself once the project is on GitHub.
- **No sync.** Watched and saved marks stay in the browser and are lost if site data is cleared.
- **No in-page player.** "Watch" opens YouTube. (The old screen had one; it never worked in the hosted page.)
- **No sideways swiping.** Some in-app browsers swallow horizontal swipes, so nothing scrolls sideways.
- **Search speed:** the index takes about 0.1 s to build and a query about 50 ms on a laptop, so typing waits 90 ms before searching.

## Deploying (owner's decision)

The app uses the show's name and caricatures of a real actor, and it is labelled as an unofficial fan guide. Publish it only if you're comfortable with that. It's plain static files, so any static host works. Upload this folder without `tools/`, `tests/`, `pipeline/`, `research/`, `archive/`, `design/` and `package.json`.

## Building the catalogue (pipeline/)

Stage 1-2 of the full-catalogue plan lives in `pipeline/`. It reads metadata only, never downloads videos, and never uses browser cookies.

1. `python -m yt_dlp ... @sonypal/playlists` lists the channel's playlists (`pal_playlists.jsonl`).
2. `python pipeline/pal_list.py` lists the videos in the 22 numbered Taarak Mehta playlists (`pal_videos.jsonl`).
3. `python pipeline/pal_search_gaps.py` searches the channel for each episode number those playlists skip (`pal_gap_hits.jsonl`, about 9 minutes).
4. `python pipeline/build_excel.py` writes `pipeline/TMKOC_SonyPAL_episodes.xlsx`: one row per episode number, a Sure/Check flag, gaps, and titles with no readable number.
5. Stage 3, SonyLIV titles: read each `https://www.sonyliv.com/shows/taarak-mehta-ka-ooltah-chashmah-1700000084/episodes/<a>-<b>` page in the browser pane (click "View More Episodes" until 100 show). `python pipeline/check/save_server.py` receives each range on localhost:5319 and writes `pipeline/check/sonyliv_titles/<range>.txt`. 4,872 episodes were read this way; 3859-3862 do not exist on SonyLIV. The first pass kept only the first 220 characters of each synopsis; 2,327 synopses are longer (max 400), so the full text was re-read (stage 3b): the save helper also takes a form POST and writes `pipeline/check/sonyliv_full/<range>.txt`, and `load_sonyliv.py` prefers it. Two page quirks: the list sometimes repeats a batch of 10, so count distinct episode numbers (not rows) when deciding the range is fully loaded, and a range read must be checked for gaps (compare against `sonyliv_titles`).
6. `python pipeline/check/fetch_all.py` fetches every Sony PAL description (metadata only, 24 yt-dlp workers, about 8 minutes, resumable) into `pal_desc_all.jsonl`.
7. `python pipeline/check/compare_all.py` scores each PAL description against SonyLIV N and N+-3 (`compare_all.json`); re-run step 4 to add the SonyLIV title and Story check columns. The check is word overlap: it finds likely slips, it does not prove the rest right (it missed the known 301 and 1301 slips because those texts are short).

8. Stage 4, fallback links for numbers Sony PAL lacks (2,090 of the 4,872 SonyLIV numbers): `python pipeline/alt/list_channel.py official https://www.youtube.com/channel/UCnSFZ-olBoLGLRUS_3RI2Aw/videos` and the same with `sab` / `UC6-F5tO8uklgE9Zy8IvbdFw` list every upload (titles and lengths only; the SAB channel has about 104,000, slow but one-off). The official 2026 series is numbered "SE 01 EP 1-500, SE 02 EP 501-600", which is the same running count as SonyLIV.
9. `python pipeline/alt/pick_candidates.py` ranks up to 3 full-length uploads per missing number (official 2026 series, other official, SAB "Full Episode", other SAB), then `python pipeline/alt/fetch_alt.py` reads their metadata (24 workers, about 6 minutes), then `python pipeline/alt/choose.py` story-checks each against SonyLIV and writes `pipeline/alt/fallback.json`.
10. Re-run step 4: the sheet "All episodes (best link)" has one row per SonyLIV number. Result: Sony PAL 2,782, Sony SAB 1,738, official channel 300, SonyLIV only 52 (no free upload found: the newest numbers 4859-4876 plus scattered ones).

Known limits: only numbers 1-3218 are searched (the highest the playlists show). Titles use more than one numbering style ("Episode N", "FE N", "Full EP-N"), and the numbers have not been compared with SonyLIV's beyond Episode 50. Episodes 1-50 were checked against captions earlier and match the new sheet for 29 of 31 Sony PAL picks.

11. Stage 6, who is in each episode (`pipeline/cast/`). `python pipeline/cast/fetch_captions.py 20` reads the Hindi auto-captions of every Sony PAL and official-channel video (about 3,100 videos; metadata and caption files only; about 35 minutes with 20 workers; resumable via `attempted.txt`). Sony SAB uploads have none. `extract_text.py` turns them into plain text (`text/<id>.txt.gz`, about 2,000 files), `count_names.py` counts how often each character is named (`counts.jsonl`; the spoken title is removed first, and the Hindi words for bullet, beautiful and cunning are not counted as names), `discover_aliases.py` shows how the recogniser spells names, `evaluate_text.py` and `evaluate_combined.py` compare against the hand-checked cast of Episodes 1-50, and `thresholds.py` sets how many mentions each character needs (`thresholds.json`; Jethalal, Daya and Dr. Hathi 1, everyone else 2). Then re-run `tools/build_data.py`.
12. Stage 6, caption-less episodes. `python pipeline/cast/pick_clips.py` finds short official-channel clips (1-14 minutes, titles like "... Ep 287") of episodes whose own video has no captions (`clips.json`: 2,475 clips for 1,721 episodes). `fetch_clip_captions.py 20` reads their captions (about 10 minutes), `clip_counts.py` counts names (`clips_counts.jsonl`), and `evaluate_clips.py` compares clip evidence with full-video captions on 200 episodes that have both (`clips_calib.json`). `build_data.py` then adds names whose summed clip mentions reach the same per-character thresholds.
13. Stage 7, short links. Some Sony PAL / Sony SAB uploads are only a part of an episode (under 15 minutes). `python pipeline/alt/short_cands.py` lists full-length official / Sony SAB uploads (title names the episode number) for every episode whose main link is under 15 minutes, `python pipeline/alt/fetch_short.py` reads their metadata, `python pipeline/alt/short_choose.py` picks one (17+ minutes, or 14+ and 3+ minutes longer) into `pipeline/alt/short_fix.json`. `tools/build_data.py` then puts it first and keeps the short upload as a backup labelled "short upload". Result (2026-11-25): 55 of 72 swapped; episodes left at 13 minutes or less get a caution note (`note`). Re-run after a data rebuild.
